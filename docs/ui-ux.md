# UI / UX Specification

Full screen-by-screen spec. The menu base is SlimUI Modern Menu 1; the HUD is custom Unity UI (Canvas, Screen Space - Overlay).

::: info CODE STATUS (2026 reconcile)
All UI **controllers and HUD widgets exist in code** and are verified against this spec (`Assets/_Game/UI/`): 11 HUD widgets, combat-feedback overlays, and the four menu controllers (main / class-select / post-match / settings). What is **not** in the repo yet is the editor-authored side: the Canvases, prefabs, sprites/icons, fonts and the SlimUI scene wiring. Treat every screen below as "logic done, scene-pending" unless its callout says otherwise.

Numbers below are cross-checked against `Assets/_Game/Shared/GameConstants.cs`, the data generated by `Carrot Clash → Generate Default Data Assets`, and the widget scripts. Material deltas are flagged in `::: info` boxes. Engineers: see [/dev/getting-started](/dev/getting-started) and `Assets/_Game/CONTRACTS.md` for the frozen API.
:::

### HUD element specifications

#### Team score bar (top center)
- Both team scores display as a number plus a fill bar.
- Fill bar reflects progress toward the 500 cap.
- Leading team bar pulses subtly green; trailing team pulses amber.
- Match timer centered between scores; turns red at <60s remaining.

#### Zone ownership indicators (below scores)
- Three small icons (A, B, C) with colour:
  - Grey = neutral / not yet captured
  - Your team colour = owned
  - Enemy colour = enemy owned
  - Flashing = being contested
  - 🔒 icon = locked (Zone C pre-minute 5)
- Tap/click on an icon shows a capture progress tooltip.

#### Kill feed (top right)
- Class icon (attacker) → arrow → class icon (victim)
- Tier-transfer badge on the attacker icon when the kill was a backstab **or** the victim held momentum (tier > 0)
- Maximum 4 entries visible (`maxVisible = 4`); newest on top, oldest recycled/fades first
- Duration: 5s per entry (`entryLifetime = 5f`), then a 0.5s fade
- Your kill: entry flashes a gold border for 0.5s (`goldBorderFlashTime = 0.5f`)

#### Crosshair
- Default: white dot with 4 very short lines. Minimal, not a distracting UI.
- Expands on hipfire; contracts and fades during ADS so the iron sight reads.
- Turns red for 0.1s on hit confirmation (`hitFlashTime = 0.1f`)
- Turns orange/gold for 0.2s on kill confirmation
- Customizable in settings (dot, cross, circle, none) (*design intent*)

::: info Code delta
`CrosshairUI.cs` ships the fixed dot-plus-four-lines style with the hipfire/ADS gap and hit/kill flashes exactly as specced. The *crosshair-style picker* (dot / cross / circle / none) is **not** implemented; `SettingsService` has no crosshair field, so that customisation is design-pending.
:::

#### Momentum ring
- Thin ring around the crosshair (12px stroke, radius ~30px)
- Fill: clockwise from 12 o'clock. Fill amount tracks the decay countdown of the current tier (decay interval `12s`).
- Colours: grey (tier 0) → class colour (tier 1) → bright warm (tier 2) → animated fire orange/white shimmer (tier 3, `MaxTier = 3`)
- Decay countdown: when < 3s before tier decay, the ring pulses with a slow flicker (`decayFlickerThreshold = 3f`)
- Tier-up animation: ring flashes white, then fills the new colour over 0.3s (tweened, `tierUpTweenTime = 0.3f`)
- Breaking to tier 0 (death): ring shatters in a particle effect, then dims to 20% alpha
- All animated states (shimmer, flicker, tier-up flash) respect the **Reduce Motion** accessibility toggle

#### HP bar (bottom left)
- Horizontal bar; green → yellow → red as HP decreases
- Below 30 HP (`LowHealthThreshold = 30`): bar pulses red plus a subtle vignette on the screen edges
- Starch Armor: a yellow segment appears above the base HP bar (the +40 temp HP, `StarchArmorAmount = 40`, visualized on top)
- Regen ticking: bar fills with a smooth animation rather than instant jumps, so the player feels the heal

#### Ability slots (bottom center, flanking the momentum ring)
| Slot | Key | Position |
|---|---|---|
| Active 1 | Q | Bottom-center left |
| Active 2 | E | Bottom-center right |

- Cooldown: fill drains clockwise from the top (same convention as the ring) in a greyscale overlay
- Ready: icon fully lit, with a brief flash animation
- On activation: icon flashes white, drain begins immediately
- Passive icon shown below the ability slots, always lit (no cooldown), greyed if the passive has a condition not met

::: info Ability input
The Q / E labels match `PlayerHUD` (`keyLabelSlot1 = "Q"`, `keyLabelSlot2 = "E"`). As with Reload, the input asset lacks `Ability1` / `Ability2` actions, so `PlayerInputBinder` polls **Q** (Active1) and **E** (Active2) directly as fallbacks.
:::

#### Ammo (bottom right)
- `28 / 30` format (current mag / mag size; pistol not shown unless active)
- Below 30% of the mag (`lowFraction = 0.30`): turns orange
- At 0: flashes red plus a "RELOAD" prompt; mid-reload the prompt reads "RELOADING"
- Reload indicator: small spinning icon shown while reloading (`spinnerSpeed = 360°/s`)

::: info Reload input
Reload is triggered by **R** (and the spinner shows during the weapon's reload time). The new-Input-System asset does **not** yet define a `Reload` action, so `PlayerInputBinder` polls the R key as a fallback. There is no fully automatic reload-on-empty in the shipped binder. See the [/dev](/dev/getting-started) docs / `CONTRACTS.md`.
:::

## 6. Settings screen

<span class="cc-status partial">Partial</span>: `SettingsMenuController.cs` + `SettingsService.cs` implement the four-tab screen, persist every value to `PlayerPrefs`, and raise `OnSettingsChanged` so live systems (camera FOV, audio mixer, Reduce-Motion gating in the HUD) react immediately. Some rows in the original design are not yet backed by the service (see delta). Tab panels and widgets are editor-pending.

### Video
- Quality preset (maps to the project's `QualitySettings` presets)
- VSync, target frame rate (30 / 60 / 90 / 120 / 144 / 240 / Uncapped)
- FOV slider (80-110°, default 90°)

### Audio
- Master, Music, SFX, Voice (separate sliders, 0-1)
- Spatial audio on/off
- Subtitles (voice callout subtitles, on/off)

### Controls
- Mouse sensitivity (X / Y independent)
- ADS sensitivity multiplier
- Key bindings (displayed, click to rebind) (*design intent*)
- Controller support (dead zones, stick sensitivity) (*design intent*)

### Accessibility
- Colourblind mode (Protanopia / Deuteranopia / Tritanopia presets), which alters class colour language
- High contrast HUD mode
- Reduce motion (disables screen shake, camera bob, momentum VFX animations) (**honoured by the shipped HUD widgets**)
- Text size (Normal / Large)
- Aim assist (toggle, for controller)

::: info Code delta: settings backed vs. design-only
`SettingsService` exposes (and persists) FOV, target frame rate, VSync, quality, the four volume sliders, spatial audio, subtitles, mouse X/Y sensitivity, ADS sens multiplier, aim assist, reduce motion, high-contrast HUD, colourblind mode and text size. These are all wired.

Not yet implemented (design-only): **resolution / window-mode** selection, the **key-binding rebind UI**, and **controller dead-zone / stick-sensitivity** controls. The Input-System asset also still lacks the Reload/ADS/Ability/Swap actions a rebind screen would target (see §4), so rebinding is gated on that asset work first.
:::

## 7. Mobile HUD adjustments

<span class="cc-status pending">Editor-pending</span>: no touch input or mobile layout exists in code yet. `PlayerInputBinder` currently binds keyboard + mouse (and a right-mouse/Q/E/R fallback) only; there is no virtual joystick, on-screen fire button or touch-to-ADS. This layout is design intent for a later mobile pass.

On mobile (portrait or landscape), the HUD reorganises for thumb reach:

```
┌──────────────────────────────────────┐
│  [A 312]    5:42    [B 287]          │
│  Zone indicators (small row)         │
│                  ·  ← crosshair      │
│               ◌─────◌               │
│                                      │
│  HP ████  72/90    ammo 28/30       │
│                                      │
│  [Joystick]    [Jump][Crouch]       │
│                [Q Ability 1]        │
│                [E Ability 2]        │
│                   [Fire] [ADS]      │
└──────────────────────────────────────┘
```

- Virtual joystick: left thumb zone (move)
- Fire button: right thumb zone
- Ability buttons: right-side cluster above fire
- Crosshair + ring: screen center, always visible
- Touch-to-ADS: available as an alternative to a dedicated button in settings
